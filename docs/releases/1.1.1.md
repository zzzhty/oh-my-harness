### Independent OMH and ATM integration

- The source checkout provides `python -m omh`, an independent standard-library
  distributor with its own default venv storage, target receipts and recovery.
  See [standalone installation](../../README.md#standalone-installation).
- `omh.omh` remains the Rust content archive; it carries skills and the shared
  Python runtime provider, and excludes the standalone installer. ATM owns static
  distribution, target policy, receipts and transactions. It calls OMH's runtime
  implementation with an explicit interpreter and separate deployment root,
  without creating OMH global installed state.
- Owner-generated `.omh-runtime` bindings persist helper execution across
  sessions. `OMH_PYTHON` is the neutral explicit override; an invalid override
  fails without choosing another interpreter. One physical target has one owner.
  The contract is [ADR 0030](../adr/0030-independent-distribution-and-shared-runtime.md).

## Changes from 1.1.0

- `ask-matt`: read the actual skill before describing it or recommending a skipped step; reading does not invoke it.
- `code-review`: discover path-specific standards and collect completed reviewer reports before claiming coverage.
- `diagnosing-bugs`: verify an authorized forced-red mutation actually changed the code or fixture.
- `grilling`: yes accepts the stated recommendation, without granting unrelated permissions.
- `handoff`: resolve platform temporary paths explicitly and report unavailable directories; user destinations take precedence.
- `implement`: resolve a ticket and its title through the existing authorized tracker before ticket-dependent work.
- `tdd`: explain what each proposed test boundary catches and misses.
- `teach`: distinguish invocation-workspace paths from skill resources and vary correct quiz answer positions.
- Global delegation: prefer fresh context and self-contained raw evidence for authorized independent review, research and alternative designs; disclose unavailable isolation. Delegation remains optional and subject to existing authorization.
- Correct obsolete release/installer documentation and assess upstream updates only on formal releases.

The upstream v1.3.1 to v1.3.2 range contains 72 changed paths: 2 adopted, 9 adapted,
60 skipped and 1 deferred. These are path counts, not skill counts. Some adapted
changes share the global delegation owner. See the [selection ledger](../../dev_docs/mattpocock-v1.3.2-review.md).
No implement-spec, multi-worktree orchestrator, chief-of-staff, scheduler,
Watcher collector, hook or separate installer is introduced. Existing deferred
implement-spec work remains deferred.
