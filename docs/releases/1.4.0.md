## What changed

- [`long-running-task`](../../plugins/workflow/skills/long-running-task/SKILL.md)
  replaces `long-running-goal`, with no compatibility alias. The former
  templates and validation scripts are no longer distributed. A short
  checkpoint supports direct execution by default. Request a native `/goal`
  separately when the host supports it; the host owns its state and lifecycle.
  Detached execution and multi-agent orchestration are separate choices.
  SOP and Prompt Strategy use the same routing.
- `research` remains an independent research skill; `orchestrate-subagents`
  and `skill-guide` likewise remain distinct. `to-spec` and `triage` use the same
  inline acceptance format (condition/action, observable result, verification)
  without depending on each other's installed resources or gaining tracker
  permissions.
- Skill guidance separates staging, application repair, tracker mutations and
  publication from adjacent read-only or drafting work. Document inventories
  stay in scope, housekeeping leaves the Git index alone, and the diagnostic
  y/n template accepts LF and CRLF without printing entered text.
- `omh status --harness` filters the overview. The bootstrap wrappers verify
  each selected target after writes. Verification failure is nonzero and
  names the affected target; it does not roll back completed writes.

The catalog is still 28 skills (maintenance 4, workflow 8, Matt Pocock
selection 16). The distribution mechanism and runtime protocol are unchanged.
The retired skill's runtime binding was removed; remaining bindings are unchanged.

## Upgrade and rollback

Use `omh update --to v1.4.0` from a managed bootstrap installation (on Windows,
`python -B -m omh update --to v1.4.0` from the managed clone), or the documented
`omh refresh` workflow from an explicit source checkout. Publication
does not update any machine. A refresh removes only unmodified OMH-owned
legacy files identified by its receipt. A user edit to an owned file blocks
refresh rather than being overwritten; review it before retrying. Manually
installed copies and unrelated files are not removed, and a legacy directory
can remain if it contains unowned files. See the
[workflow migration guide](../../plugins/workflow/README.md#long-task-migration).

Update prompts and procedures to call `long-running-task` explicitly. Existing
project documents may be read as context; nothing starts or migrates a task,
converts those files, mutates native Goal state, or inherits permissions from
old records. The previous version can be restored using
`omh update --to v1.3.0` on a managed installation, or by refreshing against the
verified `v1.3.0` checkout. Normal ownership and conflict checks still apply.
