# OMH 1.5.0

This release builds on [`v1.4.0`](https://github.com/zzzhty/oh-my-harness/releases/tag/v1.4.0)
and the tested main tree at
[`df7b621`](https://github.com/zzzhty/oh-my-harness/commit/df7b621c7a06120bc83cddee5a4ad72aff0716b1).
The `omh-v1.5.0.ref` release asset contains the commit SHA for the
`v1.5.0` tag. The default catalog now contains 30 skills:
4 maintenance, 10 workflow, and 16 Matt Pocock skills.

## What changed

- [`reframe`](../../plugins/workflow/skills/reframe/SKILL.md) clarifies an
  ambiguous problem. [`sharpen`](../../plugins/workflow/skills/sharpen/SKILL.md)
  makes an already scoped prompt easier to verify. Both require explicit
  invocation and return text without executing the rewritten task.
- [`doc-alignment`](../../plugins/maintenance/skills/doc-alignment/SKILL.md)
  can audit and curate ADR guidance by scope, keeping current decisions
  discoverable without making historical ADRs required reading. Audit mode is
  read-only. The skill name and existing ADR files have not changed.
- `omh uninstall` leaves the `omh` command in place. `omh self uninstall`
  removes the owned command without deleting installed harnesses or runtimes.
- The source includes an optional Rust manager that owns its binary, pins Python,
  and verifies content checkouts; it delegates projection to the Python
  distributor. Manager fixes constrain `--python` forwarding and verify
  installed target status after content refresh. This release does not ship
  compiled manager binaries or migrate existing shims to the Rust manager.

## Upgrade and rollback

Use `omh update --to v1.5.0` on a managed installation. On Windows, use
`python -B -m omh update --to v1.5.0` from the managed clone when using the
PowerShell bootstrap path. To restore the previous release, use the same
command with `--to v1.4.0`. The usual ownership and conflict checks still
apply. Publication does not update any machine.

## Validation

See the [repository validation commands](../../README.md#versions-and-validation).
Packaging and installed-file checks do not establish native model behavior.
